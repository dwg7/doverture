# doverture — Hokkaido Overture

北海道の建物を、**国土地理院（bvmap）**・**OpenStreetMap**・**AI生成データ**が
それぞれどう捉えているかを、空間ID（ZFXY）のセル単位で突き合わせた探索的データ分析です。

どれが「正しい」かを判定するものではありません。同じ山頂——**北海道に、どこに、
どのような形で人が住んでいるか**——を、違うルートで目指している三者を横から観察しています。

## 分かったこと

全道 27,947 の z14 セルすべてを数えた結果です。

| | 件数 |
|---|---:|
| bvmap（国土地理院）の建物 | 3,137,284 |
| Overture の建物 | 3,029,763（比 0.966） |
| 　OSM 由来 | 2,705,306（89.3%） |
| 　東アジア学術データ | 96,427（3.2%） |
| 　Microsoft ほか | 228,030（7.5%） |
| 建物ゼロのセル | 14,390（51.5%） |

**全道 0.966 という「ほぼ互角」は、向きの違う二つの現象が打ち消し合った見かけでした。**
建物密度で層化すると、すべてが単調に動きます。

| 密度(件/km²) | Overture/bvmap | Microsoft比率 | bvmap平均建物面積 |
|---|---:|---:|---:|
| 0–1 | **2.33** | **53.0%** | 218 m² |
| 10–30 | 1.44 | 20.3% | 218 m² |
| 100–300 | 1.09 | 8.6% | 135 m² |
| **300+** | **0.85** | **3.2%** | **98 m²** |

読み取れたのは、**三者が違うものを測っている**ということでした。

- **国土地理院**は市街地で小さい建物まで拾い（50m²未満が42%）、疎な土地では粒度が落ちる（6.9%）
- **OSM** はどこでも bvmap をやや下回る（0.80–1.08）が、**人がいる所には確実にある**
- **Microsoft** は OSM が薄い空白を埋める（OSM密度 <1件/km² の区画では Overture の 69.6%）。
  そして**そこでは誰も検証していない**——共和町で16点を空中写真で抽出目視したところ、
  **15点は建物ではありませんでした**（耕作地・裸地・樹林・池）
- **Google Open Buildings は日本にも極東ロシアにも1件もありません**
- **北方領土**だけは別の機構です。Microsoft がゼロで、OSM だけで bvmap を1.75倍上回ります

比率の高低そのものは優劣を意味しません。**高い側を疑う手続き（空中写真での確認）と
セットにして初めて読めます。**

詳しい経緯は [`DECISIONS.md`](DECISIONS.md)（D1–D26）に、現在地は
[`HANDOVER.md`](HANDOVER.md) にあります。

## 見る

GitHub Pages（`main` の `/docs`）で配信しています。手元で見るには：

```bash
./scripts/serve.py          # http://localhost:8779/
```

- **`/`** — Open MCT のダッシュボード。[tabularmaps/do](https://github.com/tabularmaps/do) の
  16×16 tabular map に、市区町村単位の指標を載せています。ツリーから
  **「doverture 空間IDマップ」** を選ぶと地図ビューが開きます
- **`/spatialid/`** — 空間ID(z14)パネル単体（MapLibre GL JS 6 + PMTiles + 空中写真）

地図パネルは、引くと粗いセル・寄ると細かいセルに自動で切り替わります（空間IDの階層を
そのままタイルの階層に使っているため、画面上のセルは常に約64px）。z16 まで寄ると
**建物の輪郭**が重なります。

| | 色 | 線種 |
|---|---|---|
| bvmap の建物 | アクア | 実線 |
| Overture — OSM 由来（人が引いた） | 赤 | 実線 |
| Overture — Microsoft・研究データ（未検証） | 赤 | **点線** |

**色＝どのデータセットか、線種＝誰が見たか。** 輪郭が z16 からしか出ないのは、
bvmap の建物データが z16 のタイルでしか完全でないためです（z14 では 4.5% しか入っていません）。
間引かれたものと完全なものを並べて見せないための措置です。

## 作る

```bash
./scripts/build_tiles.sh              # センサスCSV → PMTiles（検証つき）
./scripts/rollup.py                   # → docs/data/municipal.json
./scripts/analyze.py                  # 全道の分布を読む
cd spatialid && npm test && npm run build
```

`npm test` は 20 件。ブラウザを使わずに、**実際に配る PMTiles の中身**で塗りの式を
評価し、ビルド成果物が参照するファイルの存在を確かめます。

## 公開しているもの・していないもの

公開するのは**セル・市区町村単位の集計値だけ**です。そこから元の建物フットプリントは
復元できません。タイル・ジオメトリ・地物単位のテーブルは公開しません。

`docs/data/doverture-cells.pmtiles` に入っているのは、セルごとの件数と面積合計のみです。
